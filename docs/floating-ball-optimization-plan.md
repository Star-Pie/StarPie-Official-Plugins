# 悬浮球优化计划（SP-FLOATBALL-001）

## 依据与目标

依据主仓 `AGENTS.md` 的轻量、低延迟、确定性和插件边界要求，以及主仓 README / CHANGELOG 对悬浮球的产品描述：球由插件绘制，点击唤出宿主配置的轮盘，拖动改变位置，停用后可卸载。当前官方插件源码基线为 `085d192`（1.0.1）。仓库中没有单独的悬浮球 PRD，本计划把上述产品要求转成可验收的本轮范围。

目标是让悬浮球在多屏、混合 DPI 和显示器变化后始终可见，点击与拖动判定稳定，重复显示和停用不遗留窗口，同时保持单 DLL、零 NuGet 和现有 SDK 契约。

## 审阅结论（基线）

1. `BallWindow` 用 `(-1,-1)` 表示未设位置。左上方副屏上的真实负坐标会被当成首次落位，重启后球跳回主屏。
2. `ClampToVirtualScreen` 只限制在虚拟桌面的外接矩形。L 形等非矩形多屏布局的空白区域也被当成合法落点；显示器断开后没有主动重新落位。
3. 鼠标释放路径只依赖先前的 `MouseMove` 设置拖动标志。少一次移动消息或捕获丢失时，拖动可能被判成点击；获取光标失败时仍保持按下状态。
4. 球体的画刷没有冻结，和主仓的 WPF 常驻对象约束不一致。
5. 现有仓库没有悬浮球专属的几何或交互回归测试，Release 构建只能证明代码可编译。

## 本轮实施范围与顺序

- [x] 用显式位置状态替换负坐标哨兵；保留物理像素存储和混合 DPI 计算。
- [x] 按实际目标显示器的工作区限制窗口位置；在显示器拓扑、分辨率或 DPI 变化后重新检查位置，确保球完整留在一块可用屏幕内。
- [x] 在鼠标抬起时再次检查位移并落实最终位置；处理获取光标失败和丢失鼠标捕获，保证一次手势最多产生一次点击或一次位置保存。
- [x] 冻结可冻结的球体画刷，保持 UI 线程创建与清理、无焦点和宿主轮盘调用方式。
- [x] 为位置选择及拖动判定增加有意义的自动回归，覆盖负坐标屏、非矩形布局、断屏回落和阈值边界；运行插件 Release 构建、模块打包校验与 `git diff --check`。
- [x] 同步插件版本、清单与注册表，记录行为变化；留出真实设备上点击、跨屏拖动、插拔显示器、停用卸载的人工验收清单。

## 验收门槛

- 自动化（已通过）：
  - 几何与交互自动回归全部通过 (`tests/starpie.plugin.floatingball/Validate-FloatingBall.ps1`)，包含负坐标屏、L形空隙、断屏回退、点击/拖动4px阈值、画刷冻结、拖拽过程写盘抑制、WndProc防递归与光标异常防护；
  - 插件 Release 构建零错误、零警告 (`dotnet build src/StarPie.Plugin.FloatingBall/FloatingBall.csproj -c Release --nologo`)；
  - 模块打包与包结构校验全部通过 (`build/Pack-Module.ps1` + `build/Verify-ModulePackage.ps1`)；
  - 版本号三处一致（`.csproj`、`plugin.json`、`module-registry.json` 均为 1.0.2）；
  - `git diff --check` 检查通过，改动严格局限于官方悬浮球插件及配套测试与文档。
- 人工（待验收，需在实机硬件环境核验）：
  - [待验收] 负坐标副屏（如主屏左上方）保存位置后重启，能够稳定恢复在负坐标副屏原位；
  - [待验收] L 形等多屏布局中，拖拽或移动不掉落到两屏交界外的空白无显示区域；
  - [待验收] 拔掉副屏后，原本位于副屏的悬浮球在显示器拓扑变更通知后能自动回落至可用主屏工作区；
  - [待验收] 快速轻点悬浮球仅唤出一次宿主轮盘，拖拽移动过程不误触轮盘；
  - [待验收] 鼠标捕获丢失或异常时光标状态复位，不残留按下或拖拽状态；
  - [待验收] 停用插件后球窗被彻底关闭并从 UI 线程回收，ALC 能够正常卸载。
- 性能：不新增常驻轮询、全局钩子、网络调用、NuGet 或宿主热路径操作。内存和时延需在真实设备复测，构建通过不代表已达主仓基准。
