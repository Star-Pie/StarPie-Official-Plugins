# Catalog 目录

src/**/plugin.json 是官方模块元数据的事实来源；CI 会将它们生成到临时的 artifacts/generated/module-registry.json。

`module-catalog.json` 是生成的发布产物。每次模块集合 Release 都会重新生成并发布一份 catalog，为每个官方模块保留发布历史，由客户端选择最高兼容包。

仓库不会提交生成的 `module-catalog.json`。发布工作流会下载最近一次已发布 catalog，合并本次变化模块的新版本并保留历史，然后发布新的完整 catalog。

module-catalog.json 中的描述、权限和 features 来自每个发布包内的 plugin.json；详情元数据不会通过加载插件程序集推导。

## Catalog v2

schemaVersion 为 2，modules 中每个 ID 只出现一次，结构为 { id, versions: [...] }。包版本、名称、描述、API、目标框架、宿主上下界、权限、功能、资产 URL、SHA-256 和大小都属于 versions 中的不可变发布记录；没有旧客户端默认包或模块顶层 version 字段。

发布工具合并新包与上次完整历史；同版本不同包哈希／大小会被拒绝。历史要求来自原版本的 plugin.json，不从当前源清单改写。缺少历史目标框架信息时，发布阶段仅下载其原 SHA-256 对应资产补齐。客户端只读取 v2，旧 v1 缓存需手动刷新；旧客户端会拒绝 v2，但不影响已安装兼容插件运行。

主程序按宿主上下界、SDK 主次版本和目标框架选最高兼容版本；找不到时保留灰显说明，不下载。更新候选必须高于已安装版本，不自动降级。缓存保留完整历史，不存过滤结果。引导安装也使用同一选择规则。

模块包格式与 SDK 契约不因目录格式版本而提升；本次不发布或修改模块版本号。

首次从 v1 发布目录迁移时，Get-PreviousCatalog 回溯同通道已发布目录（最多读取最近 1000 个 Release）并合并历史；已有完整 v2 目录则直接复用，不再重复回溯。相同 ID/版本的历史包哈希或大小冲突会阻断发布，不静默选取其中一枚。
